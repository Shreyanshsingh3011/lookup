## `lookup-server.vercel.app` is not ours

**Do not use `https://lookup-server.vercel.app`.** No suffix, no `-sand`. It is
not this project.

Vercel hands out `*.vercel.app` subdomains from one global namespace shared by
every account on the platform, first come first served. `lookup-server` was
already taken by somebody else, so our project was assigned
`lookup-server-sand.vercel.app` instead — the `-sand` is a disambiguating
suffix Vercel generated, not a hint about an environment. There is no sandbox.

The trap is that the un-suffixed name resolves and answers. Requesting it does
not fail in a way that announces the mistake; it returns whatever that other
project serves, which is easy to read as "our API is broken" or, worse, to
believe. The client's name went the other way and did get the plain
`lookup-client.vercel.app`, which makes the asymmetry easy to forget:

- `lookup-client.vercel.app` — ours ✅
- `lookup-server.vercel.app` — **somebody else's** ❌
- `lookup-server-sand.vercel.app` — ours ✅

If you are unsure which server you have reached, ask it. `GET /api` returns a
`canonicalHost` field; if that does not come back, you are not talking to this
service.

### Other hostnames Vercel assigns

Each project also answers on a per-account alias and a per-branch alias:

- `lookup-client-shreyanshsingh3011s-projects.vercel.app`
- `lookup-server-shreyanshsingh3011s-projects.vercel.app`
- `lookup-{client,server}-git-<branch>-shreyanshsingh3011s-projects.vercel.app`

These work, but they are not the canonical names and the branch ones change as
branches come and go. Prefer the table at the top.

## Finding out what the API serves

`GET https://lookup-server-sand.vercel.app/api` returns every mounted route
with a one-line description. `GET /api/routes` is the same thing under the
other name people reach for.

The list is generated by walking Express's own router at request time, so it
cannot fall behind the code — a route that exists is listed. Only the
descriptions are written by hand, in `ROUTE_DESCRIPTIONS` in
`server/src/routes.ts`, and a test fails if a mounted route has no sentence or
a sentence describes a route that no longer exists.

`GET /api/health` is unchanged and remains the liveness check.

```
curl -s https://lookup-server-sand.vercel.app/api | jq '.routes[] | "\(.method) \(.path)"'
```

## Configuration

The server function is configured in `server/vercel.json`: all `/api/*` traffic
routes to `api/index.js`, with a 30-second `maxDuration`.

`server/api/index.js` is a committed esbuild bundle, not a build artefact to be
regenerated by Vercel. Vercel discovers functions by scanning the git tree, so
the bundle has to be in the repository. **Run `npm run vercel-build --workspace
server` and commit the result whenever anything under `server/src` changes**,
or production will keep serving the previous code while the source says
otherwise.

### Environment variables

All optional. Each has a documented fallback, and the app states in its own UI
when it is running on one.

| Variable | Effect |
| --- | --- |
| `ANTHROPIC_API_KEY` | Enables `/api/explain` and `/api/orbit-advice`. Without it `/api/ai/status` reports the feature as unavailable. |
| `TLE_FILE` | Serves orbital elements from a local file instead of Celestrak, for offline or air-gapped operation. Overrides **every** group, and single-satellite and name-search lookups too. |
| `WEATHER_FILE` | Serves the cloud forecast from a local file instead of Open-Meteo. |
| `AIRCRAFT_FILE` | Serves ADS-B aircraft from a local file instead of the live providers. |
| `SPACETRACK_USER` | Space-Track account identity. Enables `/api/spacetrack/debris`, the full public debris catalogue. Without it that route reports `unavailable` and the debris screen shows the curated four clouds and eight derelicts, saying so. |
| `SPACETRACK_PASS` | Space-Track account password. Sent in a POST body at login only — never in a URL, since a URL ends up in logs and proxies. |

### A note on Space-Track data

Raw Space-Track responses must never be committed. This repository is public and
their user agreement restricts redistribution of the catalogue, so the
integration caches **in memory only** — see the comment at the top of
`server/src/spacetrack.ts`, and the ignore rules in `.gitignore` that catch the
files if anyone ever adds a disk cache anyway.

Aggregate figures derived from it are fine and several are committed: the
per-cloud population counts in `server/src/debris.ts` came from a Space-Track
query and are dated, because those are facts about the world rather than
redistribution of their dataset.

## Follow-up: a custom domain

Both canonical URLs are Vercel-assigned subdomains. A custom domain would end
the `-sand` confusion permanently and remove the dependency on a shared
namespace we do not control. It needs a domain bought or pointed at Vercel and
then attached to each project, and is deliberately **not** part of this change.
